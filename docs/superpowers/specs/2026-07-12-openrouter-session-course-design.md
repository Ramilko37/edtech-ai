# Рабочая генерация курса через OpenRouter

## Цель

Заменить демонстрационные маршруты на настоящую генерацию персональной 7-дневной карты обучения через бесплатные модели OpenRouter. Не вводить отдельный бэкенд или базу данных. Карта, профиль и выполненные пункты существуют только в текущей вкладке браузера.

## Границы первого релиза

- Один экран прототипа остаётся на `/` и сохраняет его визуальный язык.
- Ученик задаёт тему и необязательные, несекретные сигналы персонализации: цель, профессию/контекст и начальный уровень.
- Приложение генерирует настоящую карту из семи дней, первый урок, практику и объяснение персонализации.
- «Личный кабинет» показывает единственную карту текущей сессии, её прогресс и кнопку начать заново.
- Данные удаляются при закрытии вкладки; в интерфейсе это явно указано.
- Не входят в релиз: регистрация, внешний провайдер авторизации, база данных, синхронизация между устройствами, платежи и загрузка файлов.

## Архитектура

### Серверный слой без отдельного сервиса

Добавляется Next.js Route Handler `POST /api/generate-course`. Это часть текущего приложения, а не отдельный бэкенд. Он:

1. Принимает валидированный профиль и тему.
2. Использует `OPENROUTER_API_KEY` только на сервере.
3. Вызывает совместимый с OpenAI endpoint OpenRouter с моделью `openrouter/free`.
4. Требует JSON строго согласованной структуры карты обучения.
5. Валидирует ответ перед отправкой в браузер.

Ключ передаётся только в заголовке серверного запроса и никогда не добавляется в `NEXT_PUBLIC_*`, клиентский код, логи или `sessionStorage`.

### Клиент

Клиентский компонент передаёт форму на route handler и во время запроса показывает состояние сборки. После успешной генерации он отображает возвращённую карту вместо локальных `prototypeCourses` и сохраняет объект в `sessionStorage` под версионированным ключом. При первой загрузке компонент восстанавливает данные из `sessionStorage` и открывает «кабинет» с текущей картой.

Детерминированные примеры остаются только как стартовые подсказки для темы; ошибка сети или лимита не подменяется фиктивным «сгенерированным» курсом.

## Контракт данных

Запрос:

```ts
type GenerateCourseInput = {
  topic: string;
  goal?: string;
  context?: string;
  level?: "beginner" | "basic" | "intermediate";
};
```

Успешный ответ:

```ts
type GeneratedCourse = {
  title: string;
  passport: Array<{ label: string; value: string }>;
  whyThisRoute: string;
  days: Array<{ day: number; title: string; objective: string; practice: string }>;
  firstLesson: { title: string; explanation: string; task: string; feedbackPrompt: string };
  model: string;
  generatedAt: string;
};
```

Ограничения валидатора: непустая тема, семь уникальных дней 1–7, короткие строки в безопасных лимитах, обязательные поля первого урока. Модель получает системную инструкцию: писать по-русски, не выдумывать личные факты, объяснять выбор маршрута, избегать высокорисковых рекомендаций и создавать задания для понимания, а не для выполнения работы за ученика.

## Интерфейс и состояния

1. На первом экране тема остаётся главным полем. Компактные необязательные поля уточняют цель, контекст и уровень.
2. После отправки отображается существующая анимация сборки и понятная строка «Генерируем на бесплатной модели OpenRouter».
3. Результат использует прежние блоки: маршрут, паспорт, «почему так», первый урок и практика — но питается реальными данными.
4. В шапке появляется «Мой курс». Пока есть карта в сессии, он открывает кабинет с прогрессом семи дней. Отметка дня немедленно сохраняется в `sessionStorage`.
5. При ошибке показываются причины без технических секретов: нет серверного ключа, лимит/временная недоступность бесплатной модели или невалидный ответ. Доступна повторная попытка.

## Надёжность и приватность

- Вызывается `openrouter/free`, поэтому сервис выбирает доступную бесплатную модель; конкретный идентификатор модели выводится как информационный, когда API его возвращает.
- Обработчик задаёт таймаут и не раскрывает тело upstream-ошибки клиенту.
- В браузере не сохраняются ключ, токен или персональные данные, кроме добровольно введённых полей текущей учебной карты.
- `sessionStorage` очищается при закрытии вкладки. Кнопка «Сбросить карту» удаляет данные немедленно.

## Проверка

- Юнит-тесты: валидация входа, разбор/валидация ответа модели и сериализация сессионной карты.
- Интеграционные тесты route handler: успех, отсутствие ключа, отказ OpenRouter и невалидный JSON модели.
- Ручная проверка: с ключом в `.env.local` создать курс, обновить страницу, отметить день, закрыть/открыть вкладку и убедиться, что данные исчезли только после закрытия.
- `npm run build` должен завершаться успешно без ключа: маршрут сообщает понятную ошибку только при реальном запросе.

## Конфигурация

В репозиторий добавляется `.env.example` с именем `OPENROUTER_API_KEY=`. Реальный ключ хранится только локально в `.env.local` и в настройках окружения хостинга.
