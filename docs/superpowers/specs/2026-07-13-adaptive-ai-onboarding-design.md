# Адаптивный AI-onboarding

## Цель

Заменить статический пятиэкранный опрос на короткое AI-интервью, которое действительно собирает содержательный слепок ученика до выбора темы. Пользователь должен почувствовать работу персонализации уже во время onboarding, а не только после генерации курса.

## Принципы

- Пользователь рассказывает о себе своими словами; продукт не заставляет раскладывать жизнь по абстрактным категориям.
- Ни один содержательный ответ не выбран заранее.
- OpenRouter извлекает структуру из рассказа и задаёт ровно один персональный уточняющий вопрос.
- До выбора темы собираются только устойчивые сигналы человека: опыт, знакомые контексты, интересы, желаемый результат и реальный лимит времени.
- Уровень в конкретной теме и цель конкретного курса остаются после onboarding.
- Предпочтительный формат объяснения не спрашивается в вакууме: он будет уточняться позже по реакции на реальные уроки.
- Данные хранятся только в `sessionStorage`; API-ключ остаётся на сервере.

## Поток

### 1. Рассказ

Заголовок: «Расскажите о себе как человеку, а не анкете».

Один большой textarea с вопросом: «Чем вы занимаетесь, что уже хорошо умеете и что вас по-настоящему интересует?» Минимум 30 символов, максимум 800. Рядом показано, какие типы контекста AI сможет извлечь. После отправки интерфейс показывает содержательную загрузку: роль, опыт, интересы и знакомые ситуации собираются в слепок.

### 2. Уточнение от AI

`POST /api/analyze-learner` возвращает краткое резюме, извлечённые поля и один вопрос о самом важном недостающем сигнале. Вопрос содержит три конкретных варианта ответа и возможность написать свой. Он формируется по рассказу пользователя, поэтому не повторяется для всех.

### 3. Учебный контракт

Пользователь делает только два коротких выбора:

- какой результат делает обучение ценным: разобраться в системе, применять самостоятельно, создать конкретный результат или объяснять другим;
- сколько времени реально есть на одно занятие: 10, 20 или 40 минут.

До выбора кнопка продолжения неактивна. Никаких скрытых значений по умолчанию нет.

### 4. Подтверждение слепка

Экран «Вот что AI понял о вас» показывает резюме, роль, сферу, опыт, интересы, уточняющий ответ, результат и время. Пользователь может вернуться к рассказу, убрать необязательный контекст и одним переключателем разрешить или запретить использование профиля. После сохранения открывается существующий выбор темы.

## Анализ профиля

Новый чистый модуль `lib/profile-analysis.ts` валидирует исходный рассказ и ответ модели. Анализ содержит `summary`, необязательные `role`, `domain`, `background`, `interests`, `followUpQuestion` и ровно три `followUpOptions`. Сервер делает не более двух попыток, только если модель вернула структурно неполный JSON. Сетевые ошибки и rate limit не повторяются автоматически.

## Слепок v3

`LearnerSnapshot` v3 содержит `selfDescription`, `profileSummary`, необязательные `role`, `domain`, `background`, `interests`, `followUpQuestion`, `followUpAnswer`, `successCriterion`, `dailyTime`, `language` и список разрешённых сигналов. Старые v2-профили намеренно не восстанавливаются: пользователь проходит новый onboarding заново.

## Визуальное направление

Интерфейс ощущается как начало разговора с персональным методистом, а не как settings flow. На desktop — спокойное редакционное полотно с большой областью ответа и компактной «памятью AI» сбоку. На mobile — один фокусный вопрос и фиксированный CTA. Прогресс состоит из четырёх коротких сегментов. Карточки используются только для реальных выборов, а не как контейнер для каждого текста.

## Проверка

- Unit-тесты для анализа профиля, слепка v3 и consent-filtered prompt.
- Route-тесты для валидного анализа, повторной попытки и безопасных ошибок.
- Production build.
- Browser flow: рассказ → настоящий AI-анализ → персональный вопрос → контракт → слепок → выбор темы.
- Viewports: 375, 768 и 1440 px; отсутствие горизонтального overflow и перекрытия CTA.
